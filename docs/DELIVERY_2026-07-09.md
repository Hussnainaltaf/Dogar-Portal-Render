## ✅ Task 1 — Real, openable tenant copies
- Multi-tenant is **real**, not mock: each tenant is a working copy of the portal
  backed by its own SQLite DB (`data/tenants/tenant_<slug>.db`) plus the shared
  control DB.
- Added a **`/t/<slug>/` path-mode** in `TenantResolverMiddleware` so a tenant
  copy opens **without needing custom DNS** (the old "Bind URL not open" cause).
- Portal admin table now has an **"Open"** button that launches the tenant copy.
- Proven isolation: `/t/beta/api/clients/` returns the beta office's own data;
  the root portal returns the control data — same server, separate databases.

## ✅ Task 2 — Per-tenant letterhead (office identity)

  and **printed documents** show each recruiting office's own identity.
- New **"Letterhead & Office Identity"** section in the tenant branding drawer.

## How to run
```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cd app/frontend && npm ci && npm run build && cd ../..
pm2 start ecosystem.config.cjs          # serves on :3000
```

## Enabling real messaging (optional)
Set the Twilio vars in `.env` (see `.env.example`). Leave them blank to keep
safe dry-run mode.

## Running the QA tooling
```bash
python scripts/benchmark.py --email admin@yourcompany.com --password '...' 
python scripts/pentest.py   --email admin@yourcompany.com --password '...' --fail-on-high
```
